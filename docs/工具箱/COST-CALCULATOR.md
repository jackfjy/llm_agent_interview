价格会变化，落地前记录模型 ID、地区、币种、计费档位与核验日期。模型存在、账户可用、API 支持和价格是不同问题。这里保留一个有来源的计算样本，其他模型由使用者把已核验价格填入公式，避免跨厂商、历史版本与批处理混算。

## 1. 可追溯价格样本

| 模型 ID | 档位 / 模态 | 未缓存输入 | 缓存输入 | 输出 | 核验日 |
|---|---|---:|---:|---:|---|
| o3 | 标准普通文本 | $2.00 | $0.50 | $8.00 | 2026-10-25 |

单位均为美元 / 百万 tokens。该样本不代表当前性能或性价比推荐；Batch、其他服务等级、多模态、工具调用与存储费用应按对应价格项单独处理。旧版表中的 o3 `$10/$40` 已撤下，不再用于当前核算。

自部署也有成本：GPU 租赁/折旧、空闲率、存储、网络、运维与高可用冗余。不能把“权重可下载”写成“推理免费”，也不能用激活参数量直接推断所需显存。

## 2. 成本计算公式

### 2.1 把 token 口径分清

```text
C = ((N_in - N_cached) × P_in
     + N_cached × P_cached
     + N_out × P_out) / 1,000,000 + C_tools + C_other
```

- `N_in` 是总输入 token 数，`N_cached` 是其中命中的缓存输入，满足 `0 ≤ N_cached ≤ N_in`；不要把缓存再加到总输入上。
- `N_out` 按供应商 usage 计费定义，推理 token 若已计入输出就不要再次累加。用户可见文本通常小于计费输出，不能只数屏幕上的字。
- `P_*` 取相同服务档位的单价。缓存读取与缓存写入若分开收费，要增加相应费用项。
- 工具、检索、存储、图片、音频等费用分别统计。多次重试、子 Agent 和失败调用都可能产生费用。

### 2.2 计算示例

```text
系统提示 500 + 检索文档 3000 + 问题 200 = 输入 3700 tokens
计费输出 800 tokens；无缓存、无额外工具费用
采用上述 o3 样本：
C = (3700 × 2 + 800 × 8) / 1,000,000
  = (7400 + 6400) / 1,000,000
  = $0.0138

若其中 3000 输入 tokens 命中缓存：
C = (700 × 2 + 3000 × 0.5 + 800 × 8) / 1,000,000
  = $0.0093
```

### 2.3 月度与 Agent 多步预算

`月度模型费用 = 日均请求量 × 每次平均实际费用 × 当月天数`。例如每日 10,000 次、每次 $0.0138、30 天为 **$4,140**，还没计入重试与外部服务。

Agent 任务应对每一步真实输入/输出求和。历史回填通常让输入逐步增长，不能把最后一次调用的 usage 当整个任务，也不能把最终回答的输出 token 错加到输入。另报告 `总费用 / 成功任务数`，避免失败调用被平均请求成本掩盖。

以下仅为假设 token 量的算术演示，均使用输入 $2/输出 $8、无缓存、无工具费，不能作为实际产品承诺。

| 场景 | 输入 tokens | 计费输出 tokens | 估算美元 / 次 |
|---|---:|---:|---:|
| 简单对话 | 500 | 200 | $0.0026 |
| RAG 问答 | 3700 | 800 | $0.0138 |
| Agent 单次模型调用 | 5000 | 1500 | $0.0220 |
| 5 次调用合计（假设每次相同） | 25000 | 7500 | $0.1100 |

| 摘要 | 6000 | 1000 | $0.0200 |
| 分类 | 300 | 50 | $0.0010 |

以真实输入分布统计均值与 P95；字符串字数、行数与 token 数没有固定换算比。预估 tokenizer 只做预算检查，账务以服务端 usage 和账单对账为准。

## 4. 成本优化策略与验收条件

| 方法 | 怎样判断有效 |
|---|---|
| 模型路由 | 在相同任务集上比较成功率、每成功任务费用与延迟，不能仅按标价分“简单/复杂” |
| 上下文压缩 | 检查是否丢失权限、用户约束和引用；压缩调用自身也计费 |
| 精确 / 语义缓存 | 缓存键包含租户、权限、文档版本和模型设置；测误命中与失效，不用命中率直接当节省比例 |
| 供应商前缀缓存 | 根据实际 cached usage 核算；只优化输入的一部分，不抵扣输出费用 |
| 批处理 | 核对具体模型和档位的折扣、时限与失败重提成本，不假定所有提供商都统一减半 |
| 输出上限 | 减少无用输出，同时测截断率；提前断开连接不保证服务端立即停止计费 |
| 结构化输出 | 测校验失败与重试次数；schema 合法不代表业务答案正确 |
| 微调 / 小模型 | 摊销数据、训练和部署费用，并评估分布外失败 |
| 本地与云端组合 | 加上硬件利用率、维护与冗余成本，再比较同等成功率和吞吐 |
| 重试控制 | 指数退避、并发限制、最大次数和费用预算；副作用工具使用业务幂等键 |

这些策略没有通用“节省 40–70%”保证。先测基线，再报告同一数据集和成功门槛下的变化。

## 5. 参数化核算代码（Python 标准库）

```python
from dataclasses import dataclass
from decimal import Decimal

@dataclass(frozen=True)
class Price:
    input: Decimal
    cached: Decimal
    output: Decimal

# 教学样本，使用前重新核验官方价格；不调用在线服务。
O3_SAMPLE = Price(Decimal("2"), Decimal("0.5"), Decimal("8"))

def cost(price, input_tokens, output_tokens, cached_tokens=0, extra_usd="0"):
    counts = (input_tokens, output_tokens, cached_tokens)
    if any(type(n) is not int or n < 0 for n in counts):
        raise ValueError("token 数必须是非负整数")
    if cached_tokens > input_tokens:
        raise ValueError("缓存输入不能超过总输入")
    extra = Decimal(extra_usd)
    if not extra.is_finite() or extra < 0:
        raise ValueError("额外费用必须是有限非负数")
    return (
        (input_tokens - cached_tokens) * price.input
        + cached_tokens * price.cached
        + output_tokens * price.output
    ) / Decimal(1_000_000) + extra

print(cost(O3_SAMPLE, 3700, 800))         # 0.0138
print(cost(O3_SAMPLE, 3700, 800, 3000))   # 0.0093
```

在线接入时用服务端的 usage 填入参数；Responses 的输入/输出计数与 Chat Completions 的 prompt/completion 计数是两套字段，不能照搬。缓存与推理细目按相应接口的 usage 定义读取。流式调用需获取最终 usage，缺失时记录“待对账”，不要静默记作 0。预算预检是估计，服务端用量和账单仍是最终依据。
