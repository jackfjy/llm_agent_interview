## 内容记录

新增或修改高时效内容时，在页面或增补段落记录以下四项；只修改部分内容应明确范围，不能替整章背书。

| 字段 | 必须说明 |
| --- | --- |
| last_verified | 实际核验日期，不能用计划日期或转载日期冒充 |
| versions | 协议固定版本、库版本、模型/价格日期或明确“不依赖版本”的原理范围 |
| sources | 指向支持具体断言的官方文档、发布记录、论文或本仓库案例；区分事实与推断 |
| example_status | discussion-only / unexecuted / offline-tested / sdk-boundary-tested / live-tested，说明命令、平台与跳过数 |

例如：`last_verified: 2026-10-26; versions: mcp 2.3.0 / protocol 2026-07-28; example_status: sdk-boundary-tested; sources: examples/README.md`。格式不限于 YAML，但四项含义必须清晰。

不要把安装成功当运行通过，把 mock/fixture 当在线质量，把最新规范支持推断成任意 SDK 全覆盖。引用当前状态时优先固定协议/发布版本；价格写单位、输入输出口径和核验日。公司经验必须区分个人经历、练习假设和公开招聘事实。没有来源就不称真题、必考或最强。

检查新增内部链接与锚点、40 题类别/答案/失败/追问/来源、两条 Top50 路由的链接。完整 SDK 测试应无可选 SDK 跳过；纯标准库运行的 4 项跳过应明确记录。本地已验证平台为 macOS arm64 Python 3.11.15；PR 的 Ubuntu 检查需在实际执行成功后再登记，不能提前声称 Linux 已通过。

PR 工作流是普通 `pull_request` + `contents: read`，不使用模型密钥或 `pull_request_target`，不发布站点。原部署文件仅在 dev push 或人工触发时执行；不要为学习实验修改发布分支。一次有效检查证明当前提交范围，不代表全部旧章节代码已验证。

## 依赖更新

- Node 使用 package-lock.json，验证用 npm ci。VitePress 固定稳定版 1.6.4；不通过 `npm audit fix --force` 强迁到 2.0 alpha。
- Python 安装入口是 examples/requirements.lock（59 个 SDK 运行依赖精确 pin 和哈希），examples/pyproject.toml 描述直接依赖。根 requirements.txt 只是指引。离线核心没有第三方依赖。
- 更新 SDK 先读官方接口/发布说明，重新生成锁文件，在 Python 3.11 新环境用 `--require-hashes` 实装，跑完整测试、MCP 实际通信和 demos，再同步版本说明。不要只手改 README 的版本号。

```bash
uv pip compile examples/pyproject.toml --extra sdk --python-version 3.11 \
  --generate-hashes -o examples/requirements.lock
npm update --package-lock-only --ignore-scripts
npm ci
npm audit
npm run build
```

安全审计与功能构建分开报告：构建成功不等于没有依赖通告。剩余通告的包、影响版本、开发服务器/构建/静态产物的适用范围、修复路径都应记录；不能因它是开发依赖就一概称无风险。
