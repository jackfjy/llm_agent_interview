# 企业知识库：先证明权限与证据

`last_verified: 2026-10-26` · `versions: Python 3.11.15; mcp 2.3.0; openai 3.37.0; openai-agents 0.24.0; langgraph 1.2.17`

`example_status: offline-tested` · [源码](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/rag/engine.py) · [行为测试](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/tests/test_rag.py)

## 目标与安装

实现一个能回答报销政策、展示文档版本并在无证据时拒答的小知识库。Python 3.11+，不安装额外包；以下命令均在仓库根目录执行。

```bash
python -m examples.rag.demo
python -m unittest examples.tests.test_rag -v
```

## 操作与预期输出

`KnowledgeBase.upsert(id, text, readers, version=1)` 写入或替换一份小文档，`readers` 为允许读取的 principal 集合，`'*'` 表示公开。`answer(query, principal)` 输出 `refused`、`answer` 和带 `id/version/text` 的 `sources`。demo 按以下顺序执行：

| 操作 | 应观察到 |
| --- | --- |
| 员工询问报销政策 | 摘录证据，引用版本 1 |
| 访客问同一问题 | 拒答，不含私有引用 |
| upsert 同一 ID 为版本 2 | 下一次只引用新内容与版本 2 |
| delete 同一 ID | 员工也拒答 |

可信应用从登录态决定 principal；让模型填 principal 会绕过整个安全假设。权限在分词、向量化和排序之前过滤，不能先把全部文本交给外部 reranker 再删掉无权结果。

## 排序为何可解释

本例每份文档是一个 chunk；关键词覆盖与 64 维 SHA-256 哈希向量余弦以 0.7/0.3 融合，完整短语命中再加 0.2。检查候选中的 `matched`、`phrase_bonus` 和分数，解释为什么某条排前。没有词项重叠时拒答，即使哈希碰撞产生相似度。

哈希向量没有语义理解，短语加分也不是 cross-encoder。本实验不能证明同义词召回、复杂证据推理或线上检索质量；回答是摘录，并非生成模型。生产系统要用代表性查询集分别测召回、权限泄漏、引用支撑和回答充分性。

## 失败实验

1. 用访客 principal 询问私有文档原文中的精确词，确认没有引用；观察测试中私有文本不进入向量化的断言。
2. 用相同 ID 替换文档，查询旧版本特有的词，确认旧词无法检索；仅在正文写“已更新”却保留旧索引不合格。
3. 删除后再问原问题，确认拒答。这里没有持久索引、缓存、对话历史与备份；实际产品需为每个副本设计删除传播和可核验时限。
4. 使用同义改写而不共享词项，可能拒答。这暴露教学算法的能力边界，不要通过降低权限门槛“修复召回”。

## 可选在线边界与复盘

替换为真实 embedding/reranker 前，先证明权限过滤仍发生在外部调用前，建立可回答性与引用核验，并记录模型、价格及测试集版本。这里没有提供默认在线调用，也没有运行在线模型。
