## 可靠性（8题） {#可靠性8题}

### 01. 投递成功后进程崩溃，重启能直接重试吗？

**口述答案：** 先用稳定操作键查询外部收据。确认成功就补本地 checkpoint，没有收据才进入重试；任务 ID 与 payload 不变。代价是多一次查询及对外部幂等接口的依赖，换取崩溃窗口内的去重。

**失败 / 反例：** 本地 SQLite 只保存“准备发送”，无法证明外部是否收到。没有外部原子幂等保证时，直接重发可能重复投递，应进入不确定状态并核对。

**追问：** 若最后一次尝试已耗尽预算，但外部已成功，你先检查什么？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/reliable_agent/demo.py)。

### 02. 审批后把邮件正文改了，原审批还能使用吗？

**口述答案：** 审批绑定不可变任务内容与操作版本。正文变更创建新任务并重新审批；同一任务 ID 不允许替换 payload。这样牺牲一点操作便利，避免把“批准旧内容”扩张为任意写权限。

**失败 / 反例：** 只保存 approved=true 而不绑定内容，模型或调用方可在审批后换收件人，审批记录看似完整但实际授权对象已变。

**追问：** 怎样展示让审批者确认的收件人、正文摘要与风险？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/tests/test_agent.py)。

### 03. 取消恰好发生在查询外部收据期间，怎样防止任务复活？

**口述答案：** 查询后重新读取持久状态；每次写状态在事务中检查当前终态，拒绝旧快照覆盖 cancelled。调度前再检查一次。接受协作取消的边界，不能承诺跨系统原子撤销。

**失败 / 反例：** 只在 run 开头读一次 cancelled，随后将旧 running/completed 写回，会覆盖刚发生的取消并继续产生副作用。

**追问：** 若取消之前外部已经提交，最终状态和副作用记录应如何解释？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/tests/test_agent.py)。

### 04. 工具一直阻塞，配置 timeout=1 就能一秒返回吗？

**口述答案：** 只有工具实现遵守期限或支持中断，timeout 参数才有效。本例模拟服务会协作超时；任意阻塞函数需可终止进程或远端取消协议，隔离开销与中断后不确定性必须纳入设计。

**失败 / 反例：** 线程 future 超时只让等待者返回，后台线程仍可提交副作用；随后重试会形成双重执行。

**追问：** 杀掉本地进程后，如何确定远端是否仍在工作？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/reliable_agent/engine.py)。

### 05. 服务持续报错，重启能恢复重试次数吗？

**口述答案：** 尝试数、成本和时间预留都持久化，重启读取同一任务预算。max_attempts 包含首次尝试；可重试错误仍受总预算限制。保守预留会降低可用预算，但避免崩溃清零导致无限重试。

**失败 / 反例：** 把计数存在内存，每次容器重启重新获得三次机会，持续故障时会放大下游负载。

**追问：** 预留后、实际调度前取消，为什么计数可能仍增加？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/tests/test_agent.py)。

### 06. Agent 报 completed，就能认为业务完成了吗？

**口述答案：** 检查外部收据、最终状态和效果数量，而非只看模型文本。回归同时断言状态及独立账本的一条投递；trace 用于解释过程。多一层核验成本通常小于错误报喜造成的业务成本。

**失败 / 反例：** 模型输出“发送成功”但工具失败，或本地完成标志先于外部提交，都不能成为成功证据。

**追问：** 若 trace 丢失但外部收据存在，哪些证据足以恢复？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/evaluation/cases.json)。

### 07. 把单 worker 改成多个 worker，只换数据库就够吗？

**口述答案：** 先定义任务抢占、租约与 fencing，再让状态迁移原子检查拥有者。外部仍用同一操作键幂等；增加并行度要付出竞争控制与故障回收复杂度。本例明确只支持单 worker。

**失败 / 反例：** 两个 worker 同时读 pending，均调用不幂等工具；即使最后只有一个 completed，也已经发生两次外部效果。

**追问：** 租约过期后旧 worker 继续返回，怎样避免覆盖新结果？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/reliable_agent/engine.py)。

### 08. 重试投递时，如何生成幂等键？

**口述答案：** 按业务操作生成稳定键，例如 task_id:deliver:v1；重启沿用它，内容变化则使用新操作身份并重新审批。随机 request ID 用于观测，不能代替跨重试的业务键。

**失败 / 反例：** 每次重试新 UUID 无法去重；同键不同正文若被静默接受，也可能拿旧收据冒充新内容成功。

**追问：** 外部只保留幂等键一天，超期恢复该怎样处理？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/tests/test_agent.py)。

## 上下文、记忆与 Skills（6题） {#上下文记忆skills6题}

### 09. 长任务压缩上下文时，哪些信息不能只留在摘要里？

**口述答案：** 把任务目标、约束、审批对象、操作 ID、已提交收据与待办状态保存为可查询结构，摘要只用于恢复阅读。增加结构化维护成本，换取跨窗口可核验性。

**失败 / 反例：** 摘要写“已处理”但缺少操作 ID，下一轮无法区分已投递与仅拟稿，可能重复执行。

**追问：** 恢复时先读任务状态还是先相信自然语言摘要？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/reliable_agent/engine.py)。

### 10. 聊天记忆、任务 checkpoint 和外部收据可以合一吗？

**口述答案：** 分开逻辑职责：聊天记忆帮助模型理解，checkpoint 记录运行状态，外部收据证明效果。可共用存储设施，但权限、版本与恢复接口要独立；不能用对话文字充当提交证明。

**失败 / 反例：** 用户说“上次已经批准”就改任务审批位，既没有绑定内容，也没有可信身份依据。

**追问：** 会话摘要与持久任务状态矛盾时，以什么为准？

**来源 / 案例：** [官方资料或可运行案例](https://docs.langchain.com/oss/python/langgraph/persistence)。

### 11. 用户要求忘记某条偏好，删除向量记录就够了吗？

**口述答案：** 先列数据副本：源文档、索引、缓存、会话摘要与长期记忆。按用户和版本撤销读取，后台传播删除并提供核验记录。立即阻断访问与物理清除可分阶段，但要定义期限。

**失败 / 反例：** 源数据删了，旧对话仍带着原内容进入模型；仅重建向量索引不能撤回已经发送给外部服务的数据。

**追问：** 怎样验证撤权后缓存命中也不会泄漏？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/rag/engine.py)。

### 12. 把全部工具说明和所有 Skills 正文塞进提示词有何问题？

**口述答案：** 先按 name/description 发现候选，再按任务加载相关 SKILL.md 与必要资源。节省上下文并降低无关指令干扰，代价是需要清楚的适用说明和加载路径。

**失败 / 反例：** 说明过于宽泛导致误加载，或必需依赖未载入，仍可能执行错误；渐进加载不是自动正确性保证。

**追问：** 如何测试两个相似 Skill 的触发边界？

**来源 / 案例：** [官方资料或可运行案例](https://agentskills.io/specification)。

### 13. 下载了一个能发邮件的 Skill，能立刻执行脚本吗？

**口述答案：** 把 Skill 当作待审阅指令和代码，检查来源、脚本、权限及收件人；按当前用户授权决定动作。格式描述可用工具不等于已获得账户写权限。限制能力会增加人工确认成本，却避免不可信指令扩权。

**失败 / 反例：** 脚本暗中上传本地文件；仅因 SKILL.md 写了 allowed-tools 就放行，会把工具声明误当安全隔离。

**追问：** 如何在不读取真实邮箱数据的前提下先测试 Skill？

**来源 / 案例：** [官方资料或可运行案例](https://agentskills.io/specification)。

### 14. 两个子任务都需要历史上下文，应共享全部会话吗？

**口述答案：** 只传目标、必要证据与接口，分别维护工作状态；汇总时核验产物和来源。隔离减少干扰与无关敏感信息传播，但需要明确的交接合同。

**失败 / 反例：** 共享全部会话使过期结论和另一任务的工具指令进入当前任务；过度裁剪又会丢失约束，需按产物反馈调整。

**追问：** 哪类状态必须由主任务统一持有？

**来源 / 案例：** [官方资料或可运行案例](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)。

## MCP / A2A（6题） {#mcp-a2a6题}

### 15. MCP 客户端装了新 SDK，就能声称用了新协议吗？

**口述答案：** 实际建立连接并记录 negotiated_protocol，再核对目标能力；同时记录 SDK 版本。本例实际 stdio 往返协商到 2026-07-28。锁版本增加更新成本，换取可复现定位。

**失败 / 反例：** 只打印 SDK 最新协议常量，服务端可能回退旧版；能连接也不代表所有扩展都互通。

**追问：** 如何把旧客户端兼容性写成可验证矩阵？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/mcp_tools/client.py)。

### 16. 工具调用没有抛异常，却返回 ok=false，是否成功？

**口述答案：** 区分传输/协议、工具执行与业务结果三层。本例未知工具是 is_error=true；合法 calculate 遇到非法表达式是结构化 ok=false。分层记录便于决定是否修参或重试。

**失败 / 反例：** 仅凭 HTTP 200 或请求完成就记业务成功，会把除零和恶意输入拒绝当作正确计算。

**追问：** 非法参数与暂时网络错误应使用相同重试策略吗？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/tests/test_mcp_integration.py)。

### 17. 算术工具能否用 eval 加几个字符串黑名单实现？

**口述答案：** 用 AST 白名单解释明确支持的节点，并限制字符、节点和中间数值。限制表达能力，换取可审计执行范围；本例拒绝调用、属性、下标和幂。

**失败 / 反例：** 黑名单漏掉新语法或编码变体，可能访问运行时对象；只限制结果也挡不住巨大计算的资源消耗。

**追问：** 为什么 bool 也要拒绝，虽然 Python 把它当整数子类？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/mcp_tools/tools.py)。

### 18. 本地 stdio 工具准备迁移成远程 HTTP，要加什么？

**口述答案：** 重新设计资源端身份验证、scope/audience 校验和凭证隔离，再验证所选规范与客户端。stdio 的受信进程环境不能直接变成公开网络信任模型；部署便利要让位于明确授权边界。

**失败 / 反例：** 把上游 token 原样透传给任意工具，或只验证有 token 不验证资源对象，可能发生越权。

**追问：** 为什么 stdio 成功不等于 OAuth 互通已测试？

**来源 / 案例：** [官方资料或可运行案例](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)。

### 19. 远端“查库存并给建议”应是 MCP 工具还是 A2A Agent？

**口述答案：** 固定输入输出、由调用方编排的库存查询可用 MCP；需要委派目标、跟踪 Task 和 Artifact 的自主服务可考虑 A2A。依据生命周期与责任边界选协议，复杂协议会增加状态映射成本。

**失败 / 反例：** 给一个简单查询套多 Agent 协议只增复杂度；把异步长任务伪装同步工具又容易超时丢状态。

**追问：** 谁拥有任务取消权，委派后如何返回进度？

**来源 / 案例：** [官方资料或可运行案例](https://a2a-protocol.org/latest/specification/)。

### 20. A2A 取消请求已发出，用户能认为远端任务没产生效果吗？

**口述答案：** 先确认远端任务状态及取消响应，再核对在途操作。取消是生命周期协商，不能自动回滚外部效果；需要幂等、收据与补偿策略。界面应区分请求取消和已确认取消。

**失败 / 反例：** 网络断开时把本地 cancel 标记当远端确认，远端仍可能完成付款或投递。

**追问：** 连接恢复后如何关联原任务，避免创建第二个任务？

**来源 / 案例：** [官方资料或可运行案例](https://a2a-protocol.org/latest/specification/)。

## API / 框架（6题） {#api框架6题}

### 21. 简单工具循环应该选 Responses、Agents SDK 还是 LangGraph？

**口述答案：** 先看控制需求：直接 Responses 便于掌握每轮请求；Agents SDK 提供 Runner；显式图编排可用 LangGraph。先用同一审批与幂等测试比较，再承担抽象与迁移成本。

**失败 / 反例：** 把框架的 session 当作外部投递事务，换哪个框架都仍会重复副作用。

**追问：** 本例的 LangGraph 节点为什么继续调用同一 runtime？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/reliable_agent/adapters.py)。

### 22. Responses 返回一条发送提议，怎样接入人工审批？

**口述答案：** 适配器只产出 payload 与 approved=false；应用持久化不可变任务后向人展示，授权通过再运行。保留一步确认会增加延迟，但模型提议不会自动升级成写权限。

**失败 / 反例：** 把模型输出的 approved=true 直接存库，或审批对象未显示收件人，都不能证明授权。

**追问：** 审批期间模型更新建议，如何避免批准旧界面对应新内容？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/tests/test_sdk_adapters.py)。

### 23. 接口测试用了 MockTransport，哪些结论能写进文档？

**口述答案：** 可以说真实 SDK 构造的请求字段与返回解析通过，包括 store=false；不能说在线服务、模型决策或延迟通过。传输替身让测试可重复，代价是不能覆盖网络与服务端演进。

**失败 / 反例：** 把固定响应当模型生成，再宣称 Agent 推理准确率 100%，混淆了接口合同和模型质量。

**追问：** 上线前还需哪类带预算的小流量验证？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/tests/test_sdk_adapters.py)。

### 24. Runner 能返回答案，为什么仍需独立持久化任务状态？

**口述答案：** Runner 完成一次执行与业务跨进程恢复是不同职责。本例用真实 Runner 配 fixture Model 验证提议转换，任务仍由 SQLite 保存审批、预算与收据。独立状态层增加代码，却能明确恢复语义。

**失败 / 反例：** 进程退出后只剩自然语言答案，没有操作身份与审批对象，重跑可能再次执行。

**追问：** 如何区分会话历史恢复与任务效果恢复？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/reliable_agent/adapters.py)。

### 25. 旧项目用 AgentExecutor，是否直接装最新版依赖？

**口述答案：** 先识别原版本和接口，保留可复现旧环境；按 v1 迁移指南重构到 create_agent，并逐项验证状态、middleware 与结构化输出。迁移分步进行，避免一次升级混入业务行为变化。

**失败 / 反例：** 只替换导入而沿用旧参数，可能构造失败；装最新版运行旧代码无法定位是兼容问题还是业务问题。

**追问：** 工具错误处理从旧回调迁到 middleware，如何对比行为？

**来源 / 案例：** [官方资料或可运行案例](https://docs.langchain.com/oss/python/migrate/langchain-v1)。

### 26. 历史 Assistants 示例还能作为新项目入口吗？

**口述答案：** 按官方生命周期标为历史迁移参考；新实践使用 Responses 方向，并分别核验会话状态和工具调用接口。Chat Completions 仍支持，不能与 Assistants 混同判定。迁移要保留旧任务关联和回归证据。

**失败 / 反例：** 照搬已下线 Assistants 调用让新读者无法运行；机械换成 Responses 也可能丢失 call_id 关联。

**追问：** 如何在迁移测试中核验一个工具结果归属哪个调用？

**来源 / 案例：** [官方资料或可运行案例](https://developers.openai.com/api/docs/assistants/migration)。

## RAG（6题） {#rag6题}

### 27. 为了提高召回，先全库检索后过滤权限可行吗？

**口述答案：** 先限制可访问集合，再向量化、检索及 rerank；principal 来自可信登录态。牺牲一点全库预计算便利，保证私有文本不流入未授权模型或外部排序服务。

**失败 / 反例：** 最后才从答案删私有引用，无法收回已发送给 reranker 的私有文本；用户自报 principal 也会直接越权。

**追问：** 索引已预计算时，元数据过滤与文档权限源如何保持一致？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/tests/test_rag.py)。

### 28. 政策改版后新答案仍引用旧金额，该先查什么？

**口述答案：** 跟踪文档 ID、版本与旧词项是否仍在源、索引和缓存。用相同 ID 原子替换内容和权限，再验证旧词查询不命中。本例内存索引即时替换，生产异步索引要定义版本切换策略。

**失败 / 反例：** 只新增 v2 而保留 v1 可被召回，排序仍可能选旧金额；让模型自行猜新旧不可靠。

**追问：** 更新中查询应看到旧版本还是等待新版本，怎样定义一致性？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/rag/engine.py)。

### 29. 删除成功后用户还能从历史答案看到内容，算删除完成吗？

**口述答案：** 先明确删除合同：阻止新检索与清理历史副本是两项验收。列出聊天、缓存、导出和备份，分别定义撤权与保留政策；本例只能证明本地索引删除后的拒答。

**失败 / 反例：** 用“delete 已返回”宣称所有系统清除，忽略旧对话再次携带文本或客户端已保存的引用。

**追问：** 怎样构造删除后的回归查询与缓存命中测试？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/tests/test_rag.py)。

### 30. 哈希向量实验通过，是否足以选择生产 embedding？

**口述答案：** 只能说明确定性词项融合和排序机制按断言运行；用同义改写、多语言和专有词集对真实候选模型评估召回、延迟、权限与成本。教学近似便于离线复现，无法替代语义评测。

**失败 / 反例：** 没有共享词项的同义问法会拒答；哈希碰撞也可有相似度。本例用词项门槛防碰撞误答，仍不理解语义。

**追问：** 真实 embedding 提高召回后，拒答阈值为什么需要重新校准？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/rag/engine.py)。

### 31. 每条答案都有引用，怎样判断引用确实支持答案？

**口述答案：** 核对引用版本与原文，拆分回答中的主张，检查每项是否被证据蕴含；缺证据时拒答或缩小回答。引用显示便于追溯，但增加证据充分性评审成本。

**失败 / 反例：** 相关段落不等于足以回答；本例直接摘录可访问文本，也不能据此推断复杂问题已被完整解决。

**追问：** 一条回答混合两个冲突版本，如何提示用户？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/rag/engine.py)。

### 32. 加 reranker 后准确率没涨，下一步继续调权重吗？

**口述答案：** 先分层定位：正确证据是否进入候选、排序是否前移、生成是否忠实；固定查询集对比并查看 matched/phrase_bonus。只有排序是瓶颈时才调权重，避免用调参掩盖源数据缺失。

**失败 / 反例：** 正确证据从未被召回，reranker 无法凭空补足；提升相关性分数也不保证回答充分。

**追问：** 如何用最小对照区分召回失败与排序失败？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/evaluation/cases.json)。

## 评估与成本（5题） {#评估与成本5题}

### 33. 40 个用例全部通过，能说 Agent 成功率 100% 吗？

**口述答案：** 先声明分母和成功定义。回归匹配率包含应该拒绝或失败的场景；本例 120/120 匹配预期，Agent 完成为 15/36。两者分别报告，避免负例被当成完成任务。

**失败 / 反例：** 把预算耗尽失败这一正确拒绝记成业务完成，会掩盖可用性问题；用混合样本推断线上转化率同样无效。

**追问：** 部署样本与回归样本应怎样分别采样？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/evaluation/run.py)。

### 34. 同一任务试三次，两次成功，pass@3 和 pass^3 各是多少？

**口述答案：** 对此任务的观测 any-success 为 1，all-success 为 0；跨任务分别平均。本例每次新建状态，避免前次收据帮助后次。若要预测概率，还需独立同分布假设，确定性 fixture 不提供模型概率估计。

**失败 / 反例：** 把 40 个不同输入当一个任务重复 40 次，或保留状态使第二次直接恢复，都会改变指标含义。

**追问：** 为什么不能仅用总体 p 代入公式就声称实测稳定性？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/tests/test_evaluation.py)。

### 35. 两条不同工具路径都完成退款，评估应只接受标准轨迹吗？

**口述答案：** 先检查最终金额、收件对象、授权与重复效果，再检查必要安全步骤；容许多种合法路径。精确轨迹匹配便于调试，却会错罚替代方案，宜与结果评估分开。

**失败 / 反例：** 只比调用字符串会拒绝正确替代工具；只看最终文本又可能放过未审批的退款。

**追问：** 哪些中间步骤是业务必须的不变量？

**来源 / 案例：** [官方资料或可运行案例](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)。

### 36. 离线报告 cost_units=33，可以换算成线上费用吗？

**口述答案：** 不能直接换算。本例是每次预留尝试一个模拟单位；线上需按模型、输入/输出/缓存 tokens、工具费与重试逐项记账，并固定价格日期。预留预算和实付金额分别报告。

**失败 / 反例：** 把调用次数乘一个平均单价，会漏掉长上下文、失败请求和收费工具；崩溃预留时间也不是精确延迟。

**追问：** 怎样对一次超时后重试设置总体费用上限？

**来源 / 案例：** [官方资料或可运行案例](https://github.com/jackfjy/llm_agent_interview/blob/codex/refresh-2026-10/examples/evaluation/run.py)。

### 37. 模型裁判分数提高了，怎样避免只是迎合裁判？

**口述答案：** 用有人工标签的保留集校准，检查位置、长度和表达偏差；将代码检查、最终状态和人工抽样组合。裁判降低评审成本，但不能取代业务真值或所有安全断言。

**失败 / 反例：** 调提示词只让答案更长更像标准答案，分数上升而实际引用与工具效果没有改善。

**追问：** 更换 judge 版本后如何保持历史结果可比？

**来源 / 案例：** [官方资料或可运行案例](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)。

## 后训练（3题） {#后训练3题}

### 38. 客服回复风格不一致，先用 SFT、DPO 还是 RLVR？

**口述答案：** 先用错误样本定位目标：清晰的示范格式可考虑 SFT，有可靠偏好对可考虑 DPO；只有可自动核验的结果才适合设计 RLVR。训练前保留评估集，数据与训练成本要与提示/检索方案比较。

**失败 / 反例：** 把客服礼貌度硬变成字符串规则奖励，可能训练出套话；知识过期应先修知识源，训练并不能自动保持时效。

**追问：** 如果格式正确但事实错误，奖励如何分开？

**来源 / 案例：** [官方资料或可运行案例](https://arxiv.org/abs/2501.12948)。

### 39. GRPO 省掉 critic，就不需要高质量奖励了吗？

**口述答案：** 仍需可靠奖励与同题多次采样，组内相对比较用于优势估计。组采样消耗推理预算；“无独立价值模型”不等于没有训练成本。先分析奖励分布和验证器，再考虑算法。

**失败 / 反例：** 同组输出全零奖励，缺少可区分信号；验证器只识别答案格式，模型可能钻空子而非学会正确推理。

**追问：** 全对、全错与低方差组，训练信号分别有什么问题？

**来源 / 案例：** [官方资料或可运行案例](https://arxiv.org/abs/2501.12948)。

### 40. 代码 RLVR 单测通过率提高，怎样确认不是奖励漏洞？

**口述答案：** 隔离执行环境，隐藏评估测试并覆盖边界；限制文件和网络权限，监测投机路径。把训练奖励与保留集泛化分开，增加验证器维护成本，避免模型直接攻击判分器。

**失败 / 反例：** 代码读取答案文件、改测试或针对可见样例硬编码，训练奖励提高但新输入失败；单测通过不等于安全或普遍正确。

**追问：** 怎样设计一个奖励高但实际错误的对抗样本？

**来源 / 案例：** [官方资料或可运行案例](https://arxiv.org/abs/2501.12948)。
